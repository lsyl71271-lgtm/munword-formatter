# v1.9.0 — 外交协定与联合声明；决议草案沿用原文件名

新增两种文书，网页版、macOS / Windows 安装包和安卓安装包同步更新。学标六种文书的排版规则不变，第 03 步人工修改入口保留。

## 新增：外交协定、联合声明

- **入口**：第 01 步的类型卡片多了「外交协定」「联合声明」；「从规范模板新建文件」也能新建这两种，填写签署方和事由即可生成标题和签字栏。
- **签署方自动识别**：从标题读出签署方，三方就是三方，四方就是四方。
  - 中文取「关于 / 就 / 有关」之前的部分；标题分两行、第二行以它们开头时取第一行；都没有时取标题用词（协定、联合声明等）之前的部分。
  - 英文取 between / of … on 之间的部分。
  - 「大不列颠及北爱尔兰联合王国」「Trinidad and Tobago」这类名称里的「及 / and」不会把一方拆成两方：拼起来是共用国家表里的已知名称时合并。
  - 第 03 步只需确认语言和签署方，签署方可以修改。识别不出至少两方时提示填写，不会凭空造出签字栏。
- **签字栏按签署方生成**：每一方一个「XX代表」（英文 Representative of XX），顺序与签署方一致。
  - 原稿已写的代表和姓名保留；缺的「代表」补上，缺的姓名留空供签字。原稿姓名少于代表时，按位置放在最近的代表下方并提示核对。
  - 每行最多三方，尽量平均：4 方排 2+2，5 方排 3+2；一行放不下（例如英文长名称）时再多分一行。姓名居中对齐在对应代表的正下方。
  - 签字栏含图片、域、链接、修订或隐藏文字时保留原样，提示人工核对。
- **两种版式分别按用户提供的范例**（范例本身不收入仓库）：
  - 外交协定（按 PDF 实测）：标题 16 磅加粗居中，固定行距 31.2 磅；正文 12 磅，固定行距 23.4 磅，首行缩进 2 字，两端对齐；「第X章」加粗居中；段前段后为 0。
  - 联合声明（按 DOCX 段落属性）：标题 16 磅加粗居中；正文段前 17 磅、段后 16.5 磅，单倍行距，左对齐；开头一段（「……声明如下：」）不编号，其后各段编号「1.」；引用的条文左缩进 1 字并用斜体；签字栏 1.5 倍行距。原稿已有自动编号时保留，部分有、部分没有时不补并提示。
  - 英文版用同一版式，西文字体 Times New Roman。
- **内容保护**：正文文字不改。严格内容校验只多认两种修改，并逐项核对：
  - 签字栏重建：新签字栏里的代表必须正好是授权的签署方，原有代表一个不少，姓名一个不多、一个不少；
  - 联合声明编号：段首只允许加「N. 」，其余文字不变。

## 改动：决议草案沿用原文件名

决议草案不再询问会期、提交国家和版本号，成稿的文件名就是上传文件的原名（去掉 Windows 不允许的字符）。其他文书的文件名规则不变。Python API 同样处理（`/api/format/draft-resolution` 用上传文件名）。

## 两套引擎与测试

- 浏览器引擎（`app/docx-browser.ts`）和 Python 引擎（`backend/app/treaty.py`、`backend/app/formatters/treaty.py`）实现同一套规则，规则写在 `shared/document-policy.json` 的 `treaties` 一节。
- 新增三份合成验收原稿：`12_中文外交协定`（三方，原稿只写了两位代表）、`13_中文联合声明`（四方，标题两行，没有签字栏）、`14_English_Joint_Statement`（英文，长名称换行）。全部 14 份原稿分别按两种新文书排版，两套引擎的段落、对齐、行距、缩进、制表位、字号和强调逐段相同。
- `tests/fixtures/engine-parity.json` 增加两种新文书的识别结果；`tests/treaty.test.mjs` 与 `backend/tests/test_treaty.py` 覆盖签署方识别、两种版式、签字栏补齐与换行、第 03 步修改签署方、守卫拒绝删改姓名或改动正文、决议草案文件名和模板新建。
- 桌面离线冒烟、浏览器全流程、安卓模拟器和旧 WebView 验收都加入三份新原稿，类型卡片按 8 张检查。
