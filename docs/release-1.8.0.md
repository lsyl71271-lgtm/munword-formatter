# v1.8.0 — formal country fields and one daily UI

- Official zh/en full names and UN M49 identities come from a single checked-in UNTERM/UNGEGN snapshot (2026-10-05). Whole-name aliases only; no inferred names.
- Known country aliases expand, deduplicate by ID and use stable configured sorting. Full names stay unchanged. English initial grammatical `the` is omitted for newly expanded field names, while supplied formal forms retain it.
- Clear header country/list fields only, never body prose, delegate names, quotes or document resources. Ambiguous, historical, unknown, organization and observer input stays unchanged with review warnings. Complex/semantic fields stay unchanged with reasons.
- Strict guard independently proves automatic changes from the original field and shared table. Manual step-03 edits retain their existing authorization path. Conversion records include paragraph, field, input/output, ID and check date.
- Desktop mounts `app/page.tsx`, compiled with the same `app/docx-browser.ts` and `app/globals.css`. Removed the duplicate `local_web/app.js`; local assets are reproducibly built/offline and packaged with licenses. Python API and batch CLI are retained for compatibility, sharing country data/policy and parity tests, NOT removed or falsely described as a single-codebase implementation.
- An explicitly present signatories field in a working paper is preserved/normalized with the existing warning; it is not silently erased from the Python model. No signatories field is invented.

Scope limits: country input cannot determine historical date/context; no fuzzy matching or online lookup during formatting. Manual review is still required for unresolved/complex fields. Rendering, pagination and fonts still require real Word/WPS checks; browser processing remains synchronous. The snapshot is dated, not a live guarantee of future official changes. Native Windows/macOS installers require real-device acceptance.

## Verification

- Node 162/162, Python 163/163 on Python 3.9 and 3.12, rendered HTML 2/2; production/offline builds, TypeScript and source lint passed.
- Every official name and curated alias is cross-checked in both languages, including IDs, ambiguity/entity status, displayed names, deduplication and ordering. Unicode fallback ordering uses code points in both engines.
- Field expansion, preserved formal forms, whole-name matching, unknown/historical/ambiguous/entity refusal, protected links/revisions/fields, duplicate-header refusal, strict guard rejection of unproven changes and editable step-03 behavior are covered.
- Local-only readback: 23 original acceptance inputs plus 264 prior formatted outputs, 287/287 generated by both engines without error. Text, numbering, paragraph geometry, per-character fonts/size/bold/italic/underline and page geometry matched between engines. Each engine's second pass matched its first pass exactly for all 287.
- Against the prior browser output, 228/287 full readbacks were identical. The other 59 differed only in recognized country fields and resulting header country/signature wrapping. Non-country nonblank header rows and all body rows (including body blanks) matched, as did page geometry. Country-related header blanks were intentionally excluded from this baseline comparison; they were included in cross-engine and idempotence comparisons.
- The 264 prior outputs are output-regression inputs, not a claim of rerunning 264 original corrupted inputs. Private local QA documents/reports are ignored, not shipped or committed. Automated readback is not a visual Word/WPS pagination guarantee.
