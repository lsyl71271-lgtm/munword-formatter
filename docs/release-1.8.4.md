# v1.8.4 — Numbering checks for all six document types

Before this release, all types had partial size/gap protection, but only DR had the new type-specific hierarchy/notation normalization. Now every formatter passes through one shared numbering flow; no six duplicated algorithms or sample-text special cases.

`shared/numbering-profiles.json` records the type/language profiles and source pages. Position-paper proposal lists follow pages 16/18 (`1、` or `1.`, then `a)`); section numbers remain distinct. Working-paper lists follow pages 31–35 (`1.`, `(a)`), with PART/new-introduction restarts preserved. Directives follow page 38 (`1.`, English `a.`), using the stated resolution rule for deeper ranks. DR retains pages 42–45. Both amendments follow pages 52–53 for operation numbers (`1.`); nested inserted/quoted target clauses remain untouched and are flagged for review. Deeper PP/WP formats not explicitly shown are a project extension, not a claimed handbook requirement.

The common `app/numbering.ts` / `backend/app/numbering.py` modules select profiles, resolve supported markers and parent evidence, render notation, check typed gaps/repeats and apply per-instance native presentation overrides. Roman and extended zodiac/stem sequences use the same ordinal parser as rewriting. The old duplicated continuity tables omitted Roman values and used an incomplete letter alphabet; those tables are removed. Counter values, starts/restarts, list membership, references, complex structures and resources stay protected by independent guards. The previous DR helper names were replaced rather than leaving a second unused algorithm.

Every generated document reports a type-specific `numbering-policy` check, including documents with no numbered body. That check is not a semantic correctness certificate: missing-parent evidence, conflicting ranks, unknown definitions, unsupported ranges or protected content still require a person. No-list documents are not given invented numbering; Step 03 remains available and is not filled in automated tests.

Validation: Node 203/203 and Python 200/200 passed; the static deployment smoke suite passed 2/2; the production build, typecheck, focused lint and source audit passed. New tests cover all six types, two languages, wrong borrowed notation, PP sections versus proposals, WP PART restarts, amendment references/insertions, native counter protection, ambiguous/protected paragraphs and repeated processing.

The private local regression corpus consists of 23 acceptance samples plus 264 pre-existing stress outputs, not 287 newly corrupted inputs. All 287 outputs matched across the two engines in visible text, displayed native numbering, per-character formatting, paragraph layout and page geometry; each engine's second pass was unchanged in those properties. Relative to v1.8.3, 60 files changed; all 289 visible-text changes independently satisfied the same-ordinal/same-body marker guard, with unchanged paragraph counts and page geometry. This is a structural readback check, not a claim of pixel-perfect Word/WPS rendering. Private originals, outputs and audit logs are excluded from the repository and website.
