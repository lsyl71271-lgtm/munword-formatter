# v1.8.5 — 文稿保护与边界回归修复

本次以 GitHub `main` 的 `e3deb0c` 为基线，检查浏览器/Python 引擎、共享规则、内容守卫、网页交互、预览、API/CLI、构建、打包和安装入口。基线 Node 203 项、Python 200 项测试均通过；以下问题通过额外合成输入或真实组件的受控异步响应复现。没有使用、提交或上传真实用户文稿。

## 已修复

- **小数与复合编号被误改。** 段首 `1.5 亿美元`、`1.1`、`1.2.3` 过去可能被解释成单级序号 `1`，并改成 `第一条5…` 或 `1、5…`。两套引擎和独立编号守卫现在拒绝这种部分匹配，保留数字原文；覆盖全部六种文种与重复排版。Python 对超长数字标记先检查有效位数，避免超过整数转换长度限制。
- **非可见内容被当作空行。** 只含书签结束、批注范围、权限范围或移动修订范围标记的段落，过去会先被删除，再被守卫拦截而无法导出。空行清理现在同时检查内容签名；这些段落和隐藏/删除线空白均原样保留，不放宽最终内容守卫。
- **空白列表项导致计数变化。** 空白的原生编号段也占一个序号，现在不会因视觉上为空而被删除，后续条号和交叉引用保持原有计数。
- **编号样式部分继承失效。** 段落或派生样式只覆盖 `ilvl` 时，原实现会遗漏基样式中的 `numId`，重置段落样式后丢失编号。现在按属性合并继承链与直接设置，保留明确的 `numId=0` 关闭编号，并按 OOXML 顺序写回。Python 的物化范围也包含表格与文本框段落。
- **本地化/精简样式导致后端异常。** Python 不再假设必有名为 `Normal` 的样式，改用文档实际默认段落样式；确实没有默认样式时才建立默认样式。浏览器识别默认样式的 `1/true/on` 写法保持一致。
- **重新识别残留旧成品。** 再次识别原稿时立即清除先前模型、成品、预览及校验，防止原始识别结果与上一次人工修改后的成品混用。
- **过期 API 错误污染新任务。** 异步读取失败响应后再次核对操作标识，换文件后到达的旧错误不会把旧校验记录写回页面。
- **ZIP 目录自相矛盾仍被接受。** 浏览器检查本地/中央目录的文件名、CRC、大小、磁盘号、数据边界及重叠；Python 补齐非流式本地头 CRC/大小检查。保留合法 data-descriptor 流式 ZIP 支持。
- **可修复依赖公告。** 将 `source-map-js` 从 1.2.1 定向锁定到 1.2.2，其余依赖未批量升级。对应公告：[GHSA-68fv-2mgg-jv7q](https://github.com/advisories/GHSA-68fv-2mgg-jv7q)。
- **静态构建后 lint 误扫产物。** 将 `static-site/` 及其临时目录纳入生成文件排除项，避免压缩后的发布脚本产生数千条无关诊断；源码仍完整检查。
