# 通用排版程序审计与验证

本轮修复针对通用处理流程，不按文件名、国家、议题或参考文档内容选择生产规则。第 03 步仍可人工修改；历史样本自动回归不填写该步骤。

## 已修复

- 浏览器校验曾用“发生过修复”作为内容校验通过的替代条件。现在将人工修改和结构修复单独记录，再严格对比排版前后的内容树；错误会阻止下载。
- 文字片段拆分可能丢失同一片段内的图片、域、换行或制表符。现在按节点拆分并保留控制节点；复杂段落需要整段改写时停止输出，不静默清空。
- 元数据标签必须有分隔符，避免把“国家应当……”或英文标签前缀误认为字段。没有可靠标题时不猜测无标签页首。
- 中文“第几条”、跨多个文字片段的动词和自动编号条款纳入强调及结构识别；复杂文字字号和粗斜体属性同步设置。
- 自动编号统一字号时保留符号项目的原字库，避免 Wingdings 等项目符号变乱码；损坏的编号 XML 不再静默跳过。
- 第 03 步清空字段、修改标题现在生效并记录；同名重复字段不再全部覆盖。
- 快速切换类型或文件后，旧识别/生成任务不能覆盖新状态或下载过期结果；下载逻辑合并；网络请求有超时。
- 浏览器版明确保留标点及国家顺序，不再展示实际上只对后端有效的选项。隐私说明随处理方式变化。
- 解压前检查条目数量、体积、压缩比例、目录、重复路径、加密和不支持的格式；解压后检查长度和 CRC，拒绝 XML 实体/DTD 与超大 XML。
- 后端人工覆盖参数改为字段白名单和类型/长度校验；保留未知类型的 404；CPU 密集处理移出异步事件循环；补齐原网站 CORS 来源。
- 移除后端第二套重复“补第一节”代码，结构修复对复杂内容增加保护；文字范围偏移计入制表符和换行。
- 前端复用模型类型；条款角色查询改为映射，避免逐段重复全表扫描；将 ZIP 和节点安全操作集中到单一模块。

## 验证范围

- 后端 27 项测试：原有六管线回归及新增参数/接口/文件包安全测试。
- 浏览器 27 项测试：11 个仓库内中英文样本、复杂节点保留、字号、编号、人工字段修改、异常压缩包、内容签名、40 组固定种子的碎片化与异常字号压力组合。
- 10 个历史样本：4 组坏文件与正确版本的文字/换行/制表符和指定格式断言；6 个正确样本重复处理的内容检查。样本路径可由 `MUNWORD_FIXTURE_ROOT` 指定。
- 2 项生产构建产物测试；TypeScript 严格类型检查、ESLint、生产构建。
- 工作文件输出与参考各两页进行 LibreOffice 渲染检查。使用测试环境字体映射解决渲染器中文缺字，没有改动用户原稿或系统字体。两者没有发现文字截断，但段落间距和分页位置仍有差异，不能称为像素级一致，也不能替代 WPS/Word 的原生验证。

## 尚未解决的硬伤

1. 信息被真正删除后，编号、层级、缺失标签未必能唯一恢复。短段落识别仍含启发式规则，不是语义证明。
2. 浏览器与 Python 后端仍是两套实现，共用策略不等于行为完全一致；尤其是标点、国家排序与复杂结构支持范围不同。本轮没有冒险整体重写后端。
3. 排版内容树检查不等于完整 OOXML 合规或跨软件像素级版式验证。混合文字、兼容设置、字体替换、表格、文本框及复杂编号仍需更多实际样本和原生软件检查。
4. 浏览器处理仍在主线程，大文件可能短暂阻塞界面。已加资源上限，但尚未迁移到 Worker。

## 复跑

```sh
node --test tests/docx-safety.test.mjs
.venv/bin/python -m unittest discover -s backend/tests -v
MUNWORD_FIXTURE_ROOT=/path/to/fixtures node scripts/verify-browser-regressions.mjs
pnpm build
pnpm typecheck
pnpm lint
node --test tests/rendered-html.test.mjs
```

`typecheck` 使用构建生成的 Wrangler 配置再生成本地运行时声明；该大体积自动生成文件不提交到源码。维护时保留现有锁文件，不为类型检查强制重新安装依赖。
