# 2026-10 独立审查后的修复（基于 v1.7.1）

审查报告与可复现样本不在仓库内（合成 DOCX，无真实文件）。本轮只做报告第一阶段的小步修复，学标参数、界面流程和第 03 步人工修改入口不变；自动回归不填写第 03 步。

## 内容安全

- 隐藏（vanish/webHidden/specVanish）与删除线（strike/dstrike）文字在任何改写中保持原样：含这类文字的段落不再“扁平化”重建；国家名单、签字行、第 03 步带标签字段遇到它们时保留原样并提示（第 03 步修改则中止并说明原因）。
- 两个引擎的内容守卫新增独立检查：格式化前隐藏或带删除线的字符，必须按原顺序仍隐藏/仍带删除线，否则中止输出。此前守卫不比对 run 属性，校验结果会误报“已保留”。
- 句末标点：句末文字为隐藏或删除线时不自动改标点并提示；句末是 REF 域结果或超链接时，标点写在域/链接之后，不再写进会被 Word 更新掉的域结果。

## 识别与两引擎一致性

- 语言判定写入共享策略 `language`，两引擎同一规则：英文文件中引用少量汉字不再被当成中文（浏览器曾把标题改成“决议草案”、标点改为全角）。
- 浏览器的名单结束判定与 Python 一致：主体句（如 “The Assembly of States Parties,”）、条款动词、PART 标题结束名单，不再并入附议国。
- Python 把 Word 自动编号的 0 级段落也作为行动性条款起点，以“呼吁/支持/希望”等两表共有动词开头的行动条款不再被当成序言。
- 以冒号结尾的自动编号条款之后，同一列表同级的条款不再被降为下一级。
- 页首无标签字段只在正文开始（共享 `headerBoundary`）之前识别：“一、问题背景”等编号小标题不再被当成代表；Python 页首修复按文件语言写标签，英文立场文件不再写入中文标签。
- Python 拆分内嵌子条款时不再切开超链接或修订包装（此前会被自身修复校验拒绝、整份文件 409），改为保留并提示，与浏览器一致。

## 第 03 步

- Python 立场文件带标签的页首字段，第 03 步修改不再被 409 拒绝。
- 浏览器修改字段时只改页首段落，不再改写正文中与旧值相同的段落。
- 网页国家输入框保存原始文字，逐字输入的分隔符和空格不再被吞掉。

## 包、预览与本机服务

- 大写扩展名（如 `header1.XML`）的部件同样做 DTD/实体检查；浏览器支持 UTF-16 编码的 XML 部件。
- 预览副本删除所有找不到图片来源的引用，避免宿主页面请求 `/null`。
- 本机引擎拒绝来自非本机页面且不在白名单中的浏览器 POST（403，读取请求体之前）；XML 结构过深等解析错误归为文件问题（422）。
- 依赖：lxml 统一为 6.1.3；Python ≥3.10 使用 fastapi 0.142.2 / python-multipart 0.0.32（含已公开漏洞修复）；Python 3.9（macOS `/usr/bin/python3`）使用其仍支持的最新版本 fastapi 0.128.8 / python-multipart 0.0.20。

## 发布与安装

- `scripts/package-release.py` 从 Git 索引读取受控文件；工作区有未暂存改动时拒绝打包，避免本地替换的文件进入发布包。
- Windows 启动器比较服务版本：旧版引擎占用端口时先尝试停止，无法停止则提示；安装时旧引擎停不下来即中止，不再“安装成功”却继续使用旧引擎。
